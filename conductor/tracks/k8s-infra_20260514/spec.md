# Specification: Infra K8s Base

**Track ID:** k8s-infra_20260514
**Type:** Chore
**Created:** 2026-05-14

## Summary

Criar os Helm charts da infraestrutura base do Ops Ahead em um único cluster Kubernetes, organizados por namespace, com overlay `dev` de recursos reduzidos para desenvolvimento local em k3s.

## Context

O Ops Ahead é um sistema AIOps modular em quatro camadas (dados → modelos → copiloto IA → interfaces). Toda a stack roda em Kubernetes e se descreve com três grupos de primitivas: `Deployment` (serviços de longa duração), `StatefulSet` (estado persistente) e `CronJob`/`Job` (processamento assíncrono). Esta track provisiona o cluster — sem ela nenhuma outra track tem onde rodar.

## Motivation

Pré-requisito absoluto de todas as tracks subsequentes. Pipeline de dados, modelos, copiloto e interfaces dependem dos StatefulSets e operators provisionados aqui.

## Acceptance Criteria

- [ ] `helm install` do zero em k3s sem erro manual em qualquer namespace
- [ ] Todos os StatefulSets com health check passando (Kafka, MinIO, ClickHouse, Postgres, Redis)
- [ ] NetworkPolicy aplicada: `ns: ui` só fala com `ns: ml` na porta da API; nenhum namespace acessa ClickHouse diretamente exceto `ns: data` e `ns: ml`
- [ ] Overlay `dev` funcional: 1 réplica por componente, sem HPA, sem TLS, recursos reduzidos
- [ ] ArgoCD apontando para o repositório e reconciliando o cluster após merge na `main`

## Dependencies

Nenhuma — esta é a track raiz.

## Out of Scope

- Código de aplicação (workers, APIs, modelos) — apenas infraestrutura
- TLS e certificados (cert-manager) — overlay `prod`, não `dev`
- HPA e VPA — overlay `prod`
- Keycloak (SSO) — Track 7
- Linkerd (service mesh) — pode entrar no overlay `prod` posteriormente
- Configuração de secrets reais (Vault + External Secrets) — overlay `prod`

## Risks

- **Helm charts maduros para Strimzi e Altinity Operator** — probabilidade baixa, impacto médio. Mitigação: cair para versão community (Kafka via Bitnami, ClickHouse standalone) se o operator tiver instabilidade no k3s local.

## Technical Notes

- Monorepo: charts em `infra/charts/<namespace>/`, overlays em `infra/overlays/dev/` e `infra/overlays/prod/`
- Cada chart tem um `values.dev.yaml` com recursos reduzidos (requests/limits baixos, 1 réplica, storage menor)
- ArgoCD usa `Application` CRD apontando para `infra/overlays/dev` na branch `main`
- Tópicos Kafka criados via `KafkaTopic` CRD do Strimzi: `incidents.raw`, `incidents.scored`, `alerts.burst`, `recommendations`, `actions.taken`
